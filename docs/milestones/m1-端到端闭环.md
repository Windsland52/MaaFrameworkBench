# 里程碑 1：最小端到端闭环

> 日期：2026-09-16 · 结论：**闭环成立** —— 1 个任务 + 1 个环境 + 跑 1 次 + 1 个分数 + 本报告。
> 目标来自设计定稿 §11。本轮**不接 LLM**，被测产出是手写的正确 pipeline。

## 跑出来的东西

```
node scripts/bench.ts t001-enter-inventory --system ref --seed 1 --repeat 0 --pipeline tasks/t001-enter-inventory/fixtures/correct.json
```

- run：`runs/t001-enter-inventory.ref.s1.r0`（status=succeeded，墙钟 3.1s）
- 分数：`score.json` → passed=true，四条断言全过，识别 3 次 / 点击 1 次
- 轨迹：`home` --(点 STOCK)--> `inventory`，最后读到数量 `12`

四条断言各自证的东西不一样，缺一条就有盲区：

| 断言        | 这次的值                          | 它挡住了什么                     |
| ----------- | --------------------------------- | -------------------------------- |
| `env_state` | screen=inventory                  | 停在主页却报成功 / 走错路        |
| `node_hit`  | 命中 Main.Start（题面写死的入口） | 没从约定的入口跑起来             |
| `reco_text` | 任一节点识别到 "12"               | 到了那屏却没真读画面 / 读错值    |
| `op_count`  | 识别 3 次 / 点击 1 次             | 用穷举点法把识别问题变成时间问题 |

## 判分器真的会判不过吗

"判分器把什么都判过"和"判分器工作正常"看起来一模一样，所以闭环里带了一组**已知该不过**的提交
（`scripts/verify-loop.ts`，跑 `pnpm verify`）：

| 提交                           | status    | passed   | 挂掉的断言                       |
| ------------------------------ | --------- | -------- | -------------------------------- |
| 正确实现                       | succeeded | **true** | —                                |
| 同样的行为、**不同的节点名**   | succeeded | **true** | —                                |
| 点错按钮（点在不响应的地方）   | failed    | false    | env_state / reco_text            |
| 读错数量（expected 写成 "99"） | failed    | false    | reco_text                        |
| 跑不完（墙钟 400ms）           | timeout   | false    | env_state / node_hit / reco_text |

另有一条：**同一份提交跑两次，`artifact/` 快照哈希一致**（`d3a1b9e07766`）——
"只判首次提交"这条纪律要成立，前提就是同一份东西每次哈希都一样。

## 闭环自身的三个洞（本轮修掉）

1. **提交快照漏掉了 `frames/`**。物化时早就写进工作区，但拷贝 artifact 时带着一条
   `WORKSPACE_SKIP = ['artifact', 'frames']` 的老过滤 —— 于是 agent 能改的目录不在哈希覆盖范围内。
   现在整棵拷、不过滤：漏掉任何一个目录，都等于留了一块「改了也不算」的地方。
2. **`visible` 曾指向任务包里的副本**，于是那张 PNG 进了 git（违反 §5 主仓不放二进制），
   而且物化出来是 `visible/frame-01.png`，与题面写的 `frames/` 对不上 —— 题面在骗 agent。
   现在 `visible` 只写数据集里的帧名，物化到 `frames/`；契约 §1 也改成「声明不是副本」。
3. **断言锚定了题面没约定过的名字**。task.yaml 写着 `node_hit.order: [Main.Start,
Main.AtInventory, Main.Quantity]`、`reco_text.node: Main.Quantity` —— 可 prompt 只约定了入口
   `Main.Start`。同一份正确的产出，另两个节点改叫 `OpenStock` / `ReadCount` 就挂：
   实测命中序列 `Main.Start -> OpenStock -> ReadCount`，旧断言判「顺序缺 Main.AtInventory -> Main.Quantity」。
   现在 `node_hit` 只锚定题面写死的入口，`reco_text` 不写 `node` 就是「任一节点读到过」，
   并且自检里多了一条**行为相同、只有命名不同、必须过**的提交 —— 它就是这个洞的回归测试。

## 实测撞出来、写进契约的六件事

前五条都是**跑起来才知道**的，而且症状都不指向原因：

1. **`post_bundle` 的路径是资源包根目录**（含 `pipeline/`），不是它的上一级。
   传上一级不会报错，只会静默加载不到任何节点，症状是 `task not exist`。
2. **最后一个节点只发 `PipelineNode.Succeeded`，不发 `Starting`**（3 节点流程实测）。
   只认 `Starting` 会把最后一步判成"没命中"。
3. **`PipelineNode.Succeeded` 的顶层 `name` 是父节点**，真正完成的节点在 `node_details.name`。
   用顶层 `name` 会把最后一步记到前一个节点头上。这条卡了一次判分。
4. **识别不到的节点一个 PipelineNode 事件都不发**，于是它整段从命中序列里消失。
   这与契约里"`node_detail()` 对失败节点返回空 name，判分器不能靠它判断节点是否存在"是同一条边界。
5. **未命中的 `next` 会重试到本节点 `timeout`**（默认 20s）。
   "点错按钮"那一例因此做了 22 次识别 —— 它是判据该抓的事，不是判据坏了，
   也说明 `op_count` 这条效率项不是摆设。
6. **识别结果得写进 `events.jsonl`**（本轮改的）。不写的话 `reco_text` 无从判，
   而"答出画面上的那个值"恰恰是这类任务唯一要判的东西。

## 一处与设计定稿的偏差：`frames` 能不能多点一下

设计定稿说 `frames` 是"静态图片包"，契约里也写着"输入直接返回成功、画面不变"，结论是**只够识别类任务**。
但"点对了没有"必须看得见，否则 `env_state` 断言和第 2 条轨迹断言都判不了，
而设计定稿 §11 的验收形状（"从主页进入库存页"）本身就需要两屏。

处置：给环境加了 **screen 序列 + 命中区切屏** —— 输入落在声明的矩形内就切屏，否则画面不变。
"没有应用"这条边界没破（画面是数据，不是逻辑），代价是**单屏只有一条路径**：
能容纳任意动作 = 状态转移逻辑由我们拥有，那是 `web` 环境要做的事。
契约已按实测改成这一段。

## 一处降级：画面用英文标签

原本想给帧素材画汉字（"库存"），实测 PP-OCRv6/small 对手画点阵汉字**认不出来**：

```
{"box":[108,198,226,147],"score":0.263,"text":"昌幹"}   // 想画的是「库存」
```

合成字标英文时 score ≥ 0.99。所以帧素材用英文标签（STOCK / STATU / INVENTORY / BACK），
任务是识别类任务，不靠字体考人。**真汉字画面要等真实录制件**，那是 `replay` 环境的事。

## 这一轮证明了什么 / 没证明什么

**证明了**：管道通了 —— 物化工作区 → 子进程跑（可硬杀）→ 收产物 → 判分 → 落 run 目录；
断言能区分"做对 / 走错 / 没读到 / 跑不完"；同一份提交哈希稳定。

**没证明**（下一轮才谈得上）：

- **没有真被测系统**。`--pipeline` 是替身：它把 `tasks/t001-enter-inventory/fixtures/correct.json` 那份手写的产出钉进"提交快照"，
  走的是和 agent 提交完全相同的哈希与判分路径，但**没有测到任何模型能力**。
- **隔离与防作弊没进关键路径**（契约 §7 记着）。现在工作区里能看到起始屏，
  而环境用的画面在 `data/` 里、agent 拿不到 —— 这是"暂不设防"，不是"防住了"。
- **一屏一条路径**，多路径能力还没有环境承载。
- **不能报通过率**。1 个任务、1 个系统、1 个 seed，只够证明链路，不够支撑任何分数结论。
